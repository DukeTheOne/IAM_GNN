## Architectural Decisions & Future Scaling Context

Before beginning implementation, consider the core architectural requirements designed to ensure this subsystem scales seamlessly from the Tier 1 prototype (500–5,000 nodes) into Tier 2 Master's Thesis research (50,000+ nodes, real-world Terraform/CloudFormation IaC parsing, and zero-shot TAC-Bench transfer):

1. **Rigorous Separation Between Unmasked Ground Truth and Partially Observed Views**:
   - The **Exact Symbolic Reachability Oracle** operates with omniscient access to the complete unmasked authorization graph $G = (V, E)$, establishing the theoretical detection upper bound ($100\%$ recall by definition) and formal ground-truth witnesses for all $(s, t)$ privilege escalation pairs.
   - The **Deterministic BFS Engine (PMapper Proxy)** operates strictly on the partially observed graph $G_o = (V, E_{\text{obs}})$, simulating current commercial IAM graph audit tools (e.g., NCC Group PMapper, BloodHound, AWS IAM Access Analyzer). Under Condition E (Adversarial Bridge Masking), BFS must fail by construction ($0\%$ reachability to severed crown jewels), serving as the empirical baseline to demonstrate the fundamental limit of deterministic graph traversal under missing configuration evidence.

2. **Topological Feature Engineering for Link Prediction ($O(|V| + |E|)$ Efficiency)**:
   - Classical link prediction baselines require featurizing candidate node pairs $(u, v)$ without dense $N \times N$ matrix instantiation, which would explode at $N = 50{,}000$ (requiring $2.5 \times 10^9$ entries and ~10 GB RAM).
   - Candidate edge features are computed strictly on-demand over the supervision candidate sets $E_{\text{eval}} = E_{\text{hidden}} \cup E_{\text{neg}}$ generated by `StratifiedNegativeSampler`:
     - **Local Neighborhood Metrics**: Common neighbors count $|\mathcal{N}(u) \cap \mathcal{N}(v)|$, Jaccard neighborhood similarity $\frac{|\mathcal{N}(u) \cap \mathcal{N}(v)|}{|\mathcal{N}(u) \cup \mathcal{N}(v)|}$, Adamic-Adar index $\sum_{z \in \mathcal{N}(u) \cap \mathcal{N}(v)} \frac{1}{\log |\mathcal{N}(z)|}$, Preferential Attachment $|\mathcal{N}(u)| \cdot |\mathcal{N}(v)|$.
     - **Observed Path Metrics**: Shortest path distance $d_{G_o}(u, v)$ bounded at cutoff $k \le 6$ (or $\infty$ / $-1$ if disconnected).
     - **Domain-Specific IAM Semantics**: Department matching indicator, cross-account boundary indicator, administrative privilege flags for $u$ and $v$, action bitmask cosine similarity, and high-value target indicator for $v$.

3. **Rule-Based Motif-Completion Heuristic (The Strongest Classical Comparator)**:
   - A critical academic requirement in [proposal.md](file:///c:/Users/jack6/IAM/IAM_GNN/proposal.md) and [blueprint.md](file:///c:/Users/jack6/IAM/IAM_GNN/blueprint.md) is addressing the primary reviewer objection: *"Why use a graph neural network when a deterministic rule-based heuristic could simply infer missing edges from dangling permissions?"*
   - We codify a dedicated **Motif Completion Heuristic** that scans $G_o$ for dangling structural prerequisites of known PE motifs (e.g., a principal possessing `iam:PassRole` and `lambda:CreateFunction` but lacking an observed trust edge to a compute role). It assigns prior risk scores to candidate completions based on action specificity and departmental alignment. The RGCN in Weeks 5–6 must empirically outperform this heuristic.

4. **Severe Class Imbalance & Evaluation Protocols (PR-AUC as Primary)**:
   - True hidden authorization edges are extremely sparse ($< 1:1{,}000$ positive-to-negative ratio). ROC-AUC is misleadingly optimistic under severe class imbalance because a large number of true negatives keeps the False Positive Rate artificially low.
   - We enforce **Precision-Recall AUC (PR-AUC)** as the primary evaluation metric, supplemented by Recall@K ($K \in \{10, 50, 100\}$), False Negative Rate (FNR), and Attack-Path Recovery Rate across held-out environments ($\mathcal{D}_{\text{test}}$).

## Step 4.2: Deterministic BFS Reachability Engine (PMapper Proxy) (4.0h) - [COMPLETED]

**Objective**: Implement a deterministic stateful BFS traversal engine modeling PMapper / BloodHound over partially observed graphs $G_o$, formally establishing empirical detection degradation under missing evidence.

**Implementation Details**:
1. **PMapper-Style BFS Engine (`DeterministicBFSEngine`)**:
   - Operates strictly on `HeteroData` or `IAMGraph` representing $G_o$.
   - Supports role-chaining transitions: direct membership (`MemberOf`), role assumption (`AssumesRole`), compute execution (`PassesTo`), and action permissions (`ActsOn`).
   - Strictly ignores reverse message-passing edges (`Rev*`) when converting `HeteroData` to prevent backward traversal leakage.
   - Cycle avoidance via path tracking and strict depth bounding ($k \le 6$).
   - Returns rich `BFSReachabilityResult` with `BFSPathWitness` audit trails.
2. **Condition E Blindness Verification**:
   - Formally verified that under Condition E (adversarial bridge bottleneck masking), deterministic BFS reachability to high-value targets drops to 0.0%, demonstrating the blindness of classical graph search tools.
   - Under Condition A (random edge dropout), verified monotonic degradation of BFS recall as edge masking ratio increases.
   - High-throughput execution verified: traversed 500-node enterprise graphs in under 0.05 seconds.

## Step 4.3: Classical ML & Rule-Based Baselines (6.0h) - [COMPLETED]

**Objective**: Build competitive non-neural statistical and heuristic baselines: a Tabular Random Forest classifier trained on topological pair features, and a structural Rule-Based Motif Completion heuristic.

**Implementation Details**:
1. **Topological Edge Featurizer (`EdgePairFeaturizer`)**:
   - Extracts 24 invariant structural, topological, organizational, and capability-aware features per candidate $(u, v)$ pair from $G_o$:
     - Local neighborhood overlap on undirected projection: common neighbors, Jaccard similarity, Adamic-Adar, preferential attachment, resource allocation.
     - Directed reachability in $G_o$: forward/reverse shortest path lengths (cutoff $k \le 6$) and reachability flags.
     - Degree centrality: in/out degrees for $u$ and $v$.
     - Security and organizational attributes: same/different department flags, $u$ is admin, $v$ is high-value asset, cross-account indicator.
     - Capability and action semantics: `iam:PassRole`, `sts:AssumeRole`, wildcard admin actions, and action set overlap count with 2-hop policy propagation along `AttachedWith` and `MemberOf` relations.
   - Vectorized batch extraction: precomputed degree and neighborhood lookups with per-source shortest path caching (<0.05s for 200 pairs).
2. **Tabular Random Forest Baseline (`RandomForestLinkPredictor`)**:
   - Bagging ensemble (`sklearn.ensemble.RandomForestClassifier`) configured with `class_weight='balanced'` to counter extreme positive link sparsity.
   - Provides `fit()`, `fit_from_features()`, continuous positive link confidence via `predict_proba()`, binary decisions via `predict()`, and Gini `feature_importances`.
3. **Rule-Based Motif Completion Heuristic (`MotifCompletionHeuristic`)**:
   - Domain-specific structural heuristic scanning $G_o$ for dangling privilege escalation primitives:
     - Dangling PassRole: evaluates compute capability/`iam:PassRole` against target roles.
     - Dangling Credential Minting: detects `iam:CreateAccessKey`/`CreateLoginProfile` targeting admin users.
     - Dangling Policy Attachment: detects `iam:Attach*Policy` targeting admin policies/roles.
     - Dangling Role Assumption: detects `sts:AssumeRole` targeting elevated roles.
     - Neighborhood and department affinity boosts.
   - Returns continuous scores $\in [0.0, 1.0]$ and human-readable audit explanations via `explain_pair()`.

## Step 4.4: Baseline Metrics Evaluation Suite (3.0h) - [COMPLETED]

**Objective**: Implement a unified benchmark harness computing PR-AUC, Recall@K, False Negative Rate, and Attack-Path Recovery across held-out environments ($\mathcal{D}_{\text{test}}$) under Masking Conditions A and E.

**Implementation Details**:
1. **Evaluation Metrics Engine**:
   - Primary Metric: **PR-AUC** (`compute_pr_auc`) via average precision score with degenerate single-class handling.
   - Secondary Metrics:
     - **ROC-AUC** (`compute_roc_auc`) with single-class fallback.
     - **Recall@10, Recall@50, Recall@100** (`compute_recall_at_k`) requiring strictly positive confidence scores for candidate retrieval.
     - **False Negative Rate (FNR)** (`compute_false_negative_rate`) at configurable classification thresholds.
     - **Mean Reciprocal Rank (MRR)** (`compute_mean_reciprocal_rank`) tracking retrieval position of first true positive link.
   - Downstream Security Metric: **Attack-Path Recovery Rate** (`compute_attack_path_recovery`) measuring the percentage of severed bottleneck edges ranked in top-$K$.
2. **Unified Benchmark Suite (`BaselineBenchmarkSuite`)**:
   - Supports evaluation across both PyG `HeteroData` environments and raw prediction score vectors.
   - Ingests all 4 baselines: `ExactReachabilityOracle`, `DeterministicBFSEngine`, `RandomForestLinkPredictor`, and `MotifCompletionHeuristic`.
   - Automated benchmark reporting:
     - `generate_markdown_report()`: produces GitHub Flavored Markdown comparison tables.
     - `generate_json_summary()`: produces structured machine-readable JSON dumps.
